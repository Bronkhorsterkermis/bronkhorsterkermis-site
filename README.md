# bronkhorsterkermis.nl

Website of Schutterij Eendracht van Bronkhorst. Static site built with [Astro](https://astro.build),
content edited through [Pages CMS](https://pagescms.org). Replaces the legacy PHP site (2008-era custom
CMS) in 2026.

## How it fits together

```
editor (Pages CMS web app) ──commit──▶ GitHub repo ──push──▶ host (Netlify) builds `npm run build` ──▶ dist/
developer (editor / git)   ──commit──┘
```

There is no server-side code and no database: every page is generated at build time.

## Content

| What | Where | Shown on |
| --- | --- | --- |
| Pages (Markdown) | `src/content/pages/*.md` | `/<slug>`; `home.md` is `/` |
| Kermisjaren | `src/content/jaren/<jaar>.md` | home page, newest first |
| Galerij der Koningen | `src/data/koningen.json` | `/galerij-der-koningen` |
| Programma's, notulen, uitnodigingen | `src/data/documenten.json` | `/activiteiten` |
| Foto Archief | `src/data/fotoarchief.json` | `/foto-archief` |
| Contact details (sidebar) | `src/data/site.json` | every page |
| Images | `src/assets/media/**` | referenced as `/media/...` |
| Downloads (PDF, Word, mp3, mp4) | `public/downloads/` | `/downloads/...` (same URLs as the old site) |

- A page's `bijlage` field appends one of the structured sections above to it.
- The menu is built from the pages, ordered by `volgorde`; `inMenu: false` hides a page.
- Images are referenced by their CMS path (`/media/...`) and resolved to `src/assets/media` at build
  time (`src/lib/media.ts` for data, `src/lib/remark-media.mjs` for Markdown), so Astro resizes
  them and serves WebP.
- Data files are validated at build time (`src/content.config.ts`, `src/lib/data.ts`): a broken edit
  fails the build instead of breaking the live site.
- `dist/_redirects` (generated by `src/pages/[redirects].ts`) maps the old URLs (`/4`,
  `/4/whatever.html`, `/index.php?page=4`) to the new ones using each page's `legacyId`.

## Editing (Pages CMS)

The CMS is configured in `.pages.yml`. Editors without a GitHub account are invited by email as
*collaborators* in Pages CMS; they can edit content and upload media but not change the configuration.

## Development

Requires Node.js ≥ 22.

```sh
npm install
npm run dev       # http://localhost:4321
npm run build     # output in dist/
npm run preview   # serve dist/
```

## Migration from the old site

`scripts/migrate/` holds the one-shot conversion from the legacy PHP site (pages, database dump,
images, downloads). Its output was hand-edited afterwards, so **do not re-run it** unless you want to
start over (`--force`).

```sh
python -m venv .venv && .venv/Scripts/pip install -r scripts/migrate/requirements.txt
.venv/Scripts/python scripts/migrate/build_content.py <path-to-legacy-site>
```
